# Trading safety

Hire a Trader can place real orders through Fyers. A bug here loses money, so these rules hold even when a change looks unrelated. The owner decided there is no manual trading: no terminal, no order ticket and no order route exist, and none may be added. The only way to an order is a HAT signal.

## Code in scope

- `backend/app/hat/execution/`: `tags.py` (order tags), `submit.py` (`reserve_order`, `send_order`), `order_book.py` (adoption, broker status, sale endings, `TagBook`), `fyers_adapter.py` (`FyersHatBroker`, the only `HatBroker` implementation), `fyers_payloads.py` (payloads and reply parsers), `fyers_broker.py` (transport, circuit breaker, call budget, `classify_place_reply`), `fyers_session.py`, `fyers_auth.py`, `fyers_tokens.py`, `reconcile.py`, `guard.py`, `session.py`, `gtt.py`, `modes.py` (the confirm and auto gates), `fyers_ipv4.py` (the IPv4 pin and the proxy check), `broker.py` (the contract engine and risk code depend on)
- `backend/app/hat/risk/`: `service.py` (`evaluate_signal`), `decision.py` (`decide`), `caps.py`, `sizing.py`, `kill.py`, `kill_ops.py` (kill switches), `drawdown.py` (drawdown kills, snapshot), `bots.py` (pause, ladder), `controls.py` (mode queue), `modes.py` (shadow, confirm, auto), `policy.py`
- `backend/app/hat/money.py`
- `backend/tests/hat/fakes/broker.py` (`FakeBroker`), `backend/tests/hat/fakes/fyers_sdk.py`, `backend/tests/hat/properties/`, `backend/tests/hat/conformance/test_conf_risk.py` (the structural risk rules)
- `verification/tla/OrderReconciliation.tla` and `verification/tla/KillSwitch.tla`

## Rules

1. **One path to an order.** A signal is judged by `evaluate_signal` (`app/hat/risk/service.py`), recorded by `reserve_order`, and sent by `send_order`, which is the only code that calls the broker. Add no order route, no manual ticket and no second risk or sizing function. `size_position` is called from `decide` only. CONF `risk.single_sizing_path` and `risk.no_manual_trading_path` fail otherwise.
2. **Shadow is the default and shadow never reaches the broker.** Account modes are `shadow`, `confirm` and `auto`. A bot runs confirm or auto only when every gate passes (`execution/modes.py:gate_refusal`, HAT-EXEC-012, HAT-GOV-085): its account is active and reports GTT delivery (`no_gtt_delivery`), the owner has confirmed DDPI on the account (`ddpi_not_confirmed`; `revoke-ddpi` clears it and narrows routing at once) and the risk policy in force confirms the base weights (`weights_not_confirmed`). A bot whose gates do not all pass runs shadow, and a placement re-reads them (`router._mode_refusal`), so a Take or a resumed auto entry routed before a gate closed is refused. In auto only a signal labelled high is placed without a card (`route_mode`, D149). The Fyers adapter reports GTT delivery since PR 25 (verified on the live account), so confirm and auto take effect on an active account. The stored `capabilities` are a cache of the adapter's, rewritten at every live session check: a real entry needs the adapter's own `gtt_delivery` as well (`modes.real_orders_allowed`, in the router and `send_order`), so a stored `true` never enables one; stops and sales are never gated on it. A virtual (shadow) order must not call a broker. A mode change is queued and takes effect at the next session open, never inside market hours (`execution/modes.py` reads the queue through `risk/modes.py`). When you touch a mode branch, keep a property that fails if a virtual order reaches `FakeBroker`.
3. **Orders are idempotent and tagged.** Every order has an `HT` tag (`TAG_PATTERN` in `execution/tags.py`: `HT`, a purpose letter, a sequence character, 16 characters of the signal id). Insert the `hat_order` row as `pending` with its tag and commit before the broker is called (`reserve_order`); `send_order` stamps each attempt with one conditional update on the attempt it read, so of two senders of one tag only one calls the broker. A retry of the same logical order reuses the tag, a new logical order gets the next sequence, and the 37th order of one signal and purpose is refused. An order of unknown outcome is looked up by tag before any retry, and an entry of unknown outcome is never sent again: Fyers does not enforce tag uniqueness and its book can lag, so a lookup that finds nothing leaves the entry to the fill sync and the session end (HAT-BRK-102, -103); an entry of an earlier session is never rejected on today's book: it ends only when the holdings show no shares beyond HAT's other positions of the symbol, else it is alerted URGENT `entry.unresolved`. A lost day stop, sale or entry is taken as never landed only on a second absent read of the book at least the settle wait after the first (`position_desk.AbsentReads`), a lost sale sent today holds back a new stop as a working one does, and `make_room` does not let a sale go beside an unsettled stop when the holding baseline shows the owner's shares of the symbol: the broker refuses a second sell only when HAT owns every share. A tag the broker holds twice is a `duplicate_ht_order` mismatch; every fill is recorded (never refused) so the shares stay under the stop, and an entry filled beyond its quantity raises URGENT `fill.excess`. A GTT carries its stop's HT tag (`orderTag`), but a lost GTT answer is never retried: once it is older than the settle wait it is settled against the broker's GTT book (`HatBroker.gtts()`, by its tag first, else an untagged GTT by symbol, side, quantity and trigger, never another HAT tag or a foreign one) and adopted or ended (`protect.StopDesk.settle_lost`). A lost sale is settled by its tag before an exit decides to send. A lost stop or sale the book shows with shares already sold is never adopted bare: it waits for the fill sync, which adopts it with its fills (`position_desk.found_verdict`), so no stop is placed over shares sold. Orders with a foreign tag or none are out of scope for HAT, except the sale one of HAT's GTTs became when it triggered (a CNC SELL carrying the GTT's tag, bare or `GTT`-prefixed, or an untagged one of the GTT's quantity at the GTT's limit price): the fill sync attributes it to that GTT and may only change it to a market sale (`StopDesk.market_sale`, HAT-EXEC-066), never its quantity, side or symbol.
4. **Every order field reaches the broker, exactly.** `FyersHatBroker` turns each `OrderIntent` into one Fyers payload (product CNC, a finite positive price, the stored broker symbol) and raises `InvalidIntentError` before any SDK call for anything else. Assert the exact payload per order type and per GTT in `tests/hat/properties/test_tags.py` and `test_fyers_broker.py`.
5. **Risk runs on every entry, and exits are never blocked.** `evaluate_signal` never raises: a missing or unreadable input is a REJECT with a reason from the enumerated set, and it never falls back to a hard-coded price. Exits are never blocked by a risk gate, a kill switch, a reconciliation mismatch or the reconciliation state: an exit, a sale or a protective stop (placed, moved or resized) is accepted in every state (D118). No risk function takes an override, bypass or force switch (CONF `risk.no_gate_override_path`). There is no `DEV_MODE`: an entry needs an OPEN session from the trading calendar. A position spanning a corporate action not rescaled (HAT-EXEC-142) or one the rescale cannot handle (HAT-EXEC-144) has its exit evaluation withheld, since its prices are on the wrong scale; that refuses no exit: its broker stop stays where it is and `/flatten` still sells it (capped at the shares the broker holds).
6. **Kill switches halt entries only, and only HAT's own switches do.** Account kill, bot kill, health kill and pause make a bot manage-only (no new entries; stops and exits keep running). A drawdown or manual kill or a pause also withdraws the bot's entries still working at the broker (`EntryCancel.withdraw`, a cancel, never an order), and a confirmed `/flatten` trips the account kill before it sells. A drawdown or manual kill re-arms by hand with a second confirmation; a health kill clears itself when the checks are healthy. The legacy VCP halt flag is not read. Change `risk/kill.py`, `risk/kill_ops.py`, `risk/drawdown.py` and `KillSwitch.tla` together.
7. **Fail closed when the broker is unavailable.** A missing client, an open circuit (`BROKER_CIRCUIT_OPEN`, `PROCESS_BREAKER`) or a failed read raises `BrokerUnavailableError`; it never returns an empty list or a zero that reads as "no positions" or "order placed". A write with an unknown outcome is `unconfirmed`, never a rejection. No entry is placed on a trade date until the first reconciliation of that date has succeeded (`ExecutionGuard.reconciled_for`, keyed by trade date, so yesterday's success never opens today); a later failed routine run never closes the gate. A failed reconciliation only ever blocks new entries: stops and sales always go out (rule 5, D118). A mismatch blocks entries for the bot or account and never auto-closes or auto-adopts a position. An order or trade row without an HT tag that cannot be read is skipped and counted; an HT-tagged one fails the read. A failed read of the stored broker symbols refuses the order unsent (`broker_unavailable`), never guessing the `-EQ` symbol.
8. **Money math is exact.** Use `Decimal` (`app/hat/money.py`: `to_decimal`, `to_money`), never float, for prices, notional, P&L and sizes. A float or a non-finite number in a risk or broker input is refused. Round only when building the broker payload, to the instrument's tick size.
9. **One session owner and one token store.** Each broker account has one session owner that serialises its broker calls (`SessionRegistry.acquire`). The Fyers token lives only in `fyers_tokens.token_store`; no other module reads or writes a token file or the Fyers credential variables. Every login goes through `FyersAuthService.exchange`, which, once a Fyers account is active, saves a token only for an active account's user; before the first account is onboarded (onboarding needs a token) any user is accepted. The account lookup is built into the service, so no caller can skip it (HAT-DEC-BD5).
10. **Never leak broker errors or secrets.** Results carry fixed codes (`CODE_*`), not broker text. Log the full error server-side if needed, but never log or return a token, a secret or the raw text of a broker error.

## Testing

- Never call the real Fyers, NSE or Telegram endpoints. Use `FakeBroker` (`tests/hat/fakes/broker.py`: the Fyers transport `FyersHatBroker` calls; it records every call in `calls`, injects read failures, place, modify and cancel replies, and can open the circuit; its place replies come from the real `classify_place_reply`) or `RecordingSdk` over the real `FyersBroker`. `FakeBroker` is the only fake broker; CONF `no_duplicate_fakes_or_authorities` refuses a second one.
- Verify by reading the diff against the rules above and running the change on real data (never placing orders). Tests only for small pure functions (sizing, stop and fill maths, parsers, state rules); never a test that runs a backtest, the pipeline or a full database on generated data.
- Run only the tests for the files you changed plus `tests/hat/conformance`. CI runs the full suite.
